Item tags

The default keep/discard filters refer to #ffdeathrules:keep_on_death and #ffdeathrules:discard_on_death. Both ship empty, preserving vanilla defaults. Add item IDs to keep favorite gear or destroy clutter. Discard wins if an item matches both tags. Vanishing processing still comes first.

On Minecraft 1.21.1 and 1.21.11, write data/ffdeathrules/tags/item/keep_on_death.json. On 1.20.1 and 1.20.6, use data/ffdeathrules/tags/items/keep_on_death.json. Use the same folder and discard_on_death.json for destruction.

{
  "replace": false,
  "values": [
    "minecraft:elytra",
    "minecraft:diamond_pickaxe",
    {"id": "anothermod:favorite_tool", "required": false}
  ]
}

For discard-on-death, the same format might list minecraft:rotten_flesh and minecraft:wooden_sword. Tags use vanilla datapack semantics, including nested tags and replace. Create your own namespace/item tag and reference it in a rule filter with #namespace:tag. Missing optional mod IDs do not make the pack fail.

Reload

Use vanilla /reload after editing tags. Membership is checked from the current registry holders for every death. Profiles remain unchanged unless you edit/reload their world rule file. FFDeathRules has no custom datapack codec or command-based rule format; permissions, teams and player overrides use commands or the API.
