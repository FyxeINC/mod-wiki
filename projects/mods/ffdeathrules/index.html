FFDeathRules

Modrinth ↗CurseForge ↗Source ↗

Overview

FFDeathRules gives servers control over death inventory, XP and messages. Rules can differ by permission node, scoreboard team or player UUID, with persistent live operator commands and an API for team/permission mods.

Inventory and curses

Choose VANILLA (follow keepInventory), ALL, HOTBAR (slots 0–8), or NONE. Keep armor/offhand separately and match items by ID, #item tag or namespace wildcard. Discard means destroy, not drop, and wins over retention. Vanishing is processed first by default; VANILLA with keepInventory preserves vanilla's behavior. Binding remains on retained equipment; dropping it on death is legal vanilla behavior. Durability penalties can break retained equipment.

Owner-only drops reserve items and XP bottles for the dead player's UUID until they despawn. Hoppers and other mods can still interact with dropped entities; this is pickup ownership, not a secure storage mechanism. Extra modded accessory inventories are outside vanilla inventory processing.

Experience

Use percentages of total XP points, not levels, for recovery and retention. Both percentages at -1 preserve vanilla loss and its XP-drop events. An explicit drop percentage with keep=-1 retains the remaining percentage; an explicit keep percentage can also leave a portion permanently lost. Floor rounding loses at most the fractional remainder and never creates XP. Drop plus keep cannot exceed 100. XP bottles recover an exact point value; large drops compress into at most 64 bottles. Ordinary bottles keep their vanilla behavior.

Death messages

Use vanilla, all-player, team-only, private, silent or nearby announcements, optional PvP-only announcements, custom text and private recovery coordinates. The death screen uses the custom message when enabled even if the public audience is NONE. Public coordinates are opt-in template placeholders; private location reminders do not broadcast them.

Rule precedence

  1. Global TOML defaults.
  2. Persistent world defaults.
  3. Matching permission profiles, ascending priority then node name.
  4. Vanilla scoreboard-team profile.
  5. Registered API providers, ascending priority then provider ID.
  6. Persistent player UUID overrides.

Only supplied fields override earlier values; lists replace lower-priority lists. A death snapshots its rules. Changes affect the next death, while pending kept items/XP restore according to the original snapshot, including after a restart or disabling the mod.

Compatibility

FFUtilities is bundled (0.2.14 on 1.20.1 to 1.21.11, 0.2.15 on 26.x). Fabric requires Fabric API. There are no automatic third-party team/permission integrations: use built-in OP thresholds, exact-node grants or an API bridge. Mods that replace death drops, graves or respawn inventory require integration testing. Vanilla-mode XP keeps loader hooks; custom XP amounts/bottles own the emission and bypass XP-drop modifier hooks. Other mods' consumed-XP flags are respected. Server rules require the mod on the server; client config screens are optional.
