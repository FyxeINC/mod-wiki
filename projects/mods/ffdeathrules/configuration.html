Configuration

Global defaults live in config/ffdeathrules-common.toml. enabled=true controls new deaths; pending restoration always completes. Generated config screens are available on NeoForge 1.21.1+ and Fabric 1.21.1+ through Mod Menu. On these screens, the keep/discard item filter lists support adding entries; new entries start as minecraft:stone and can be edited before saving. Both lists may be empty. Other targets use file editing. The three sections independently control inventory, experience and death messages.

TOML item filters are lists, for example keepItems = ["#minecraft:pickaxes", "minecraft:elytra"]. Command/API selectors use comma-separated text; [] explicitly clears an inherited list. Binding curses are not removed. Vanishing destruction takes precedence over discard and keep filters when respectVanishing is true.

Operator commands

All commands require OP level 2. Changes take effect for future deaths and save immediately. Use online player names or offline UUIDs. Team names and subjects containing spaces use quoted Brigadier strings. Values after set are greedy text: write templates directly without outer quotes.

/deathrules default set <key> <value>
/deathrules player <name-or-uuid> set <key> <value>
/deathrules team <scoreboard-team> set <key> <value>
/deathrules permission <node> set <key> <value>
/deathrules permission <node> priority <integer>
/deathrules grant <name-or-uuid> <node>
/deathrules revoke <name-or-uuid> <node>
/deathrules inspect <online-player>
/deathrules list
/deathrules reload

Keys omit the TOML section, for example inventory, xpDropPercent and messageTemplate. Each scope supports reset <key> to inherit again, clear to remove the profile, or no subcommand to show its stored patch. Clearing a permission profile also removes its priority; grants remain harmless until a profile exists again.

/deathrules default set inventory NONE
/deathrules default set xpDropPercent 25
/deathrules permission deathrules.vip set inventory HOTBAR
/deathrules permission deathrules.vip priority 10
/deathrules grant Alex deathrules.vip
/deathrules player Alex set keepArmor true
/deathrules player Alex set keepItems #minecraft:pickaxes,minecraft:elytra
/deathrules player Alex set discardItems minecraft:rotten_flesh
/deathrules team Builders set xpBottles true
/deathrules team Builders set messageAudience TEAM
/deathrules default set messageTemplate {player} met {cause} in {dimension}
/deathrules player Alex reset keepArmor

Permissions

op.0 through op.4 profiles match vanilla permission-level thresholds. Custom nodes require an exact persistent grant or a positive registered API permission resolver. There is no wildcard grant inheritance or automatic LuckPerms binding. Higher priorities apply later; equal priorities sort by node name. Scoreboard-team membership and API provider results are checked live at death.

Message controls

Templates support {vanilla}, {player}, {killer}, {cause}, {dimension}, {x}, {y}, {z}. A missing killer becomes “the environment”. Templates are single lines up to 1024 characters; rendered text is limited to 240 characters for older packet limits. Plain custom templates do not use command execution or formatting codes.

VANILLA respects scoreboard team visibility; custom audiences deliberately select their own audience. TEAM includes the dead player and their team. NEARBY is restricted to the same dimension. NONE silences chat announcements while retaining the death-screen message. respectShowDeathMessages=false permits announcements even with the gamerule off. Private coordinates are independent of public visibility.

Persistence and reload

Command and persistent API changes are stored under the world's ffdeathrules/rules.json, schema 1. Player entries are UUID-based. Writes use temporary-file replacement and roll back if saving fails. /deathrules reload rereads this world file; TOML uses the loader's config reload mechanism. Back up the world before manual profile edits. A malformed file is preserved; fix it and reload. Invalid combined XP percentages fall back to vanilla for that death and report an error, so use inspect after combining profiles.

{
  "schema": 1,
  "defaults": {"xpDropPercent": "25"},
  "players": {},
  "teams": {"Builders": {"keepArmor": "true"}},
  "permissions": {"deathrules.vip": {"priority": 10, "rules": {"inventory": "HOTBAR"}}},
  "grants": {"00000000-0000-0000-0000-000000000001": ["deathrules.vip"]}
}
