FFModsSubfolders

Modrinth ↗CurseForge ↗Source ↗

Overview

Loads mods from nested folders in the mods directory.

Features

  • Organize other mods into subfolders and disable entire folders by suffix.
  • Includes Sinytra Connector integration and configurable scan behavior.

Getting started

  1. Put FFModsSubfolders itself directly in mods.
  2. Create some subfolders and move your other NeoForge mods into them.
  3. Start the game. Look for [mod scan] in the log for a scan summary and any warnings.

Rename a folder to end in .disabled to skip everything inside it, including deeper folders. For example, mods/testing.disabled/ is ignored. Renaming it back enables it again on your next launch. Folder suffix matching is case-insensitive.

Configuration

After the first launch, edit config/ffmodsubfolders-common.toml. Changes affect the next launch because mod discovery happens before normal configuration registration. Config editing mods can also show the translated setting names and tooltips.

Group Setting Default Purpose
general enabled true Enable recursive scanning.
general disabledFolderSuffix .disabled Skip folders ending with this nonblank suffix.
general maxScanDepth 32 Maximum folder depth, from 1 to 256.
logging logIndividualSubfolders true Log each scanned folder.
logging logEmptySubfolders false Include empty folders in normal logs.
logging warnOnDuplicateJarNames true Warn about repeated jar filenames.
sinytraConnector enableConnectorIntegration true Pass scanned folders to Connector when available.

The default depth of 32 counts mods/a/ as level 1. Symlink loops are skipped. Unreadable folders, empty jars and duplicate filenames produce diagnostic messages.

Compatibility and limitations

  • FFModsSubfolders must stay directly in mods. Its startup scanner can't discover itself.
  • Minecraft 1.20.6 through 1.21.8: the early wrapper relay supports embedded mod jars such as Sodium's NeoForge packaging. Sodium should still stay at the top level if you need its pre-window GPU-driver workarounds. A startup hook can't be replayed after it has already run.
  • Minecraft 1.20.4 and 1.21.9 or newer: mods providing early startup services, custom mod locators, graphics bootstrappers or loading-screen replacements must stay directly in mods. These versions use different startup systems, with early services discovered before subfolder scanning. Regular mods still load from subfolders; the log warns when it finds an early-service jar there.
  • Sinytra Connector: where a compatible Connector version exists, keep Connector itself directly in mods. The integration passes subfolder locations to Connector for the Fabric mods it supports. Connector compatibility has been checked on 1.21.1 only. This is not native Fabric-loader support.
  • Folder paths containing commas can't be passed to Connector. Native NeoForge scanning still works, and the log names the affected folders.
  • Only one early loading-screen provider can be active. Unusual startup mods need checking individually; a successful ordinary-mod scan doesn't verify every hook.
  • There is no datapack support.

Installation and startup services

Choose the jar for your Minecraft version and keep FFModsSubfolders directly in mods. No other mod is required. On 1.20.4 and 1.21.9 or newer, other mods providing early startup services must also stay directly in mods; misplaced jars produce a warning. Connector compatibility was previously checked on 1.21.1 and is not verified for the new targets.
