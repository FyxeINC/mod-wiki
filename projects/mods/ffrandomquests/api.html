This guide describes the public API in the current source version 0.0.6. Use the dependency guidance below and check that the mod is loaded when integrating conditionally.

Public API (for other mods)

Packages: com.randomquests.api

QuestTypeRegistry

Extend built-in quest generation and progress without replacing the mod.

Target lists (optional — registry scans already pick up most mod content)

QuestTypeRegistry.addKillTargets(ResourceLocation...);
QuestTypeRegistry.addCollectTargets(ResourceLocation...);
QuestTypeRegistry.addMineTargets(ResourceLocation...);
QuestTypeRegistry.addCraftTargets(ResourceLocation...);
QuestTypeRegistry.addBiomeTargets(ResourceLocation...);
QuestTypeRegistry.addEntityTargets(ResourceLocation...); // breed/tame

Custom generators

QuestTypeRegistry.registerCustomGenerator(QuestType.KILL, (player, level, period, shared, difficulty, random) -> {
    Quest quest = myCustomQuest; // your custom kill quest generation logic
    quest.setTarget(QuestTarget.entity(ResourceLocation.fromNamespaceAndPath("mymod", "boss_entity")));
    return quest; // or null to fall back to the built-in generator
});

Quest#setTarget(QuestTarget) takes one of QuestTarget's five record variants (entity/item/block/biome/key, all static factories on QuestTarget), or null for "any." KILL additionally supports quest.setRequiredWeapon(ResourceLocation) for a weapon requirement alongside the entity target.

Progress reporting & listeners

QuestTypeRegistry.reportProgress(player, QuestType.KILL, myEntityId, 1);
QuestTypeRegistry.addProgressListener((player, quest, amountAdded) -> { ... });
QuestTypeRegistry.addCompletionListener((player, quest) -> { ... });

MainGoalRegistry

MainGoalRegistry.registerPersonalGenerator((player, level, serverGoal, difficulty, random) -> {
    long now = com.randomquests.util.GameTime.now(level);
    MainGoal g = new MainGoal(UUID.randomUUID(), MainGoalType.CUSTOM, false,
        Component.literal("Defeat the Mod Boss 3 times"), difficulty, now, 3);
    g.setTargetKey("mymod:boss_kills");
    return g; // or null to skip this turn — retried among the other pool entries
});
MainGoalRegistry.reportCustomProgress(player, "mymod:boss_kills", 1);
MainGoalRegistry.addCompletionListener((player, goal) -> { ... });

A registered generator is offered in the same weighted pool as built-in personal goal types, not a separate lottery.

Design note

Prefer relying on RegistryPools automatic scans. Use the explicit API when:

  • Your content is not discoverable by path/tag heuristics
  • You need a completely custom quest generator
  • You want to push progress from non-standard events

Internally, built-in quest types and main-goal types are each driven by a small registry (QuestTypeDefinition/QuestTypeDefinitions and MainGoalDefinition/MainGoalDefinitions) instead of switch statements — this only affects mod authors reading the mod's own source, not the public API above.

RewardRegistry

com.randomquests.api.RewardRegistry extends rewards. addCommonItems(ResourceLocation...), addRareItems(ResourceLocation...), and addLootTables(ResourceLocation...) add candidate IDs. registerProvider(RewardProvider) supplies custom rewards. The read-only getters expose registered candidates and providers. Register during setup, before quest rewards are generated.

RewardRegistry.addRareItems(ResourceLocation.fromNamespaceAndPath("mymod", "relic"));

For a genuinely new kind of reward (not just new content for an existing one), register a CustomRewardKind by key and attach it with QuestReward.custom(...):

ResourceLocation kindId = ResourceLocation.fromNamespaceAndPath("mymod", "unlock_recipe");
RewardRegistry.registerCustomKind(kindId, new RewardRegistry.CustomRewardKind() {
    public void grant(ServerPlayer player, CompoundTag data) {
        MyRecipeUnlocks.unlock(player, data.getString("recipeId"));
    }
    public String describe(CompoundTag data) {
        return "Recipe unlocked: " + data.getString("recipeId");
    }
});
CompoundTag data = new CompoundTag();
data.putString("recipeId", "mymod:super_pickaxe");
quest.addReward(QuestReward.custom(kindId, data));

data is an opaque CompoundTag your handler owns the shape of; it round-trips through save/load unmodified. A handler that throws is caught and treated as a no-op.

DifficultyRegistry

Contribute an additive factor to the dynamic-difficulty breakdown, the same way RewardRegistry contributes reward content:

DifficultyRegistry.registerFactor((player, level, period) -> MyReputation.get(player) / 100.0);

The value is added alongside the built-in factors (base, player level, world age, play time, distance, dimension/equipment, adaptive rating, death penalty) before the period multiplier and difficulty-range clamp are applied. A factor that throws is caught and ignored.

Main goal and quest progress calls need a ServerPlayer. Use namespaced target keys for custom progress to avoid collisions with other mods.
