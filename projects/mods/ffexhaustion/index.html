FFExhaustion

Modrinth ↗CurseForge ↗Source ↗

Overview

Tracks player fatigue from actions with configurable recovery and effects.

Features

  • Server authoritative exhaustion ranges from 0 to 1.
  • Configure costs for movement and combat, recovery, and optional status effects.

FFUtilities is included in this mod JAR (0.2.15 on 26.x, 0.2.11 on older versions); no separate library download is needed.

Continuous HUD updates are batched for up to five ticks. Server API queries remain authoritative; local client code should use the synced client cache. Changing attribute effect entries clears their previous modifiers, and invalid numeric entries are ignored.

How exhaustion works

Exhaustion is a per-player value from 0.0 to 1.0, saved with the player and controlled by the server. Install the mod on the server and on clients.

  • Sprinting and swim-sprinting build exhaustion and can slow movement.
  • Floating in water (optional, off by default) builds exhaustion while in water and not standing on a block.
  • Jumping has base and sprint-jump costs. Sprint-jump horizontal speed scales with exhaustion (height is unchanged).
  • Landing after a long enough fall adds exhaustion scaled by fall distance.
  • Attacking has separate hit and deliberate air-miss costs; mining doesn't count as a miss. High exhaustion slows attack speed.
  • Shields: holding block drains exhaustion.
  • Recovery starts after a delay and can use custom equations, with bonuses for standing still or sneaking on the ground.
  • Threshold potion effects (optional, off by default) apply mob effects above configurable thresholds.
  • Attribute modifiers (optional, off by default): fixed threshold modifiers and continuous scaling modifiers driven by exhaustion.
  • Player level (optional): vanilla XP level can reduce gain and recovery delay.
  • Death: copyOnDeath (default off) keeps exhaustion through death; otherwise it resets.
  • HUD: six icon stages, optional shake that ramps from zero at the configured threshold to full intensity at 100% exhaustion, configurable anchors and text. A shake threshold of 1 or higher disables it; text stays still. Continuous HUD updates are batched for up to five ticks.

Configuration

Server settings control gains, recovery and penalties. By default, recovery starts after 40 ticks and removes 0.005 exhaustion per tick, with extra recovery while standing still or sneaking on the ground. Floating gain, threshold potion effects and attribute effects are off by default. Client settings control the HUD position, text and shake. Invalid numeric config entries are ignored, and changing attribute entries removes their previous modifiers.

The in-game config screen exists on 1.21.1 and newer (on Fabric through Mod Menu); on older versions, edit the config file.

Attribute entries use attribute IDs. From Minecraft 1.21.2 the IDs have no generic. prefix (minecraft:movement_speed); on older versions write minecraft:generic.movement_speed.

Compatibility details

Optional compatibility settings are grouped under the server config compat section.

  • Better Combat: its attributed weapons use Better Combat hit and miss costs, including multi-hit and miss tracking. compat.better_combat.suppressVanillaAttackTax defaults to true; set it to false to add the regular hit and miss costs as well. Mining stays free of combat miss costs.
  • VC Gliders: drains exhaustion while gliding and drops the player at a threshold.
  • FFItemWeight: exhaustion gain scales by encumbrance level.

Loader notes

Swim-sprinting slows movement speed everywhere. On Forge and NeoForge it also slows swim speed; Fabric has no separate swim speed attribute, so that extra slowdown doesn't apply there.
