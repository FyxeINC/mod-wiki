API entry and dependencies

FFAnimalCare 0.3.0 provides API version 2 in com.fyxe.ffanimalcare.api. The entry point is AnimalHungerApi; register portable callbacks with HungerListener. The interface is shared by Fabric, Forge and NeoForge.

Compile against the artifact for your exact Minecraft version and loader: com.fyxe.ffanimalcare:ffanimalcare-<minecraft>-<loader>:0.3.0. For example:

// NeoForge
compileOnly("com.fyxe.ffanimalcare:ffanimalcare-1.21.1-neoforge:0.3.0")
// Fabric
modCompileOnly("com.fyxe.ffanimalcare:ffanimalcare-1.21.1-fabric:0.3.0")
// Forge 1.20.1
modCompileOnly("com.fyxe.ffanimalcare:ffanimalcare-1.20.1-forge:0.3.0")

Artifacts use the workspace's configured Fyxe Maven registry after publication, or a local publication during development. FFAnimalCare is a separate runtime mod; do not shade/copy its classes. Its bundled FFUtilities needs no separate player download.

For optional compatibility, declare ffanimalcare as optional in loader metadata and isolate API references in an integration class loaded only when the mod is installed. NeoForge uses type="optional" with versionRange="[0.3.0,)"; Forge uses mandatory=false. Fabric uses suggests with a >=0.3.0 range. Check with your loader's ModList/FabricLoader before invoking the integration class.

Queries

MethodContract
isAffected(Animal)Current config/exclusion/listener eligibility. Does not imply tracking has started.
isTracked(Animal)Persisted activation flag, available on both sides. It remains saved while the mod is disabled or an animal is excluded.
hunger(Animal)Latest hunger on either side, 0 full to 1 starving. Queries do not advance or activate hunger.
snapshot(Animal)Optional server-only Snapshot with tracked, hunger, lastBredTime, breedingDelayRemaining, hungerPauseRemaining, individualMultiplier, careExperience and careLevel. lastBredTime is -1 before breeding; individualMultiplier is -1 before a roll is assigned. Durations are remaining world ticks.
effectiveRate(Animal)Configured/care/datapack/listener-adjusted gain per world tick, on the server game thread; returns 0 on clients or the wrong thread. May initialize an enabled individual roll for a tracked animal. The recovery pause separately suppresses elapsed gain.
canBreed(Animal)Generic tracked/age/hunger/cooldown/canFallInLove gates. Does not check for a compatible partner or every species' pregnancy/AI condition.

Server mutations

Call mutations on the server game thread. They respect global enablement, exclusions and eligibility vetoes; client/wrong-thread or recursive callback mutations return false. Finite hunger values are clamped to 0..1. Read snapshots instead of accessing internal HungerState/HungerAccess.

MethodBehavior
activate(Animal, double initialHunger)Explicitly opt in an untracked animal. Cancellable; already-tracked animals return false.
setHunger(Animal, double value)Advance current hunger, then set a tracked animal's value through the API change callback. Does not activate wild animals.
reduceHunger(Animal, double amount)Positive normalized hunger reduction for a tracked animal, after catch-up. An actual drop starts recovery; a fully-fed animal can accept an operation without a value change.
fed(Animal, Player, double reduction)Call after your own food consumption. Can atomically activate and reduce hunger; reports MOD_FEEDING and updated particle/text feedback. Player may be null. Cancellation before commit leaves a wild animal untracked. Caller owns food recognition/consumption.
grassEaten(Animal)Report completed custom grazing using grassHungerReduction; does not activate wild animals. Emits GRASS feeding/particle feedback when accepted.
startBreeding(Animal)Advance hunger and start love mode through generic gates and the breeding veto callback. Native/custom AI still owns partner compatibility and offspring creation.
breedingCompleted(Animal)Call once for each parent after actual custom offspring creation. Records world time/random cooldown, resets love and replaces vanilla adult age cooldown, then reports completion. Does not create offspring.

Reduction amounts are hunger units, not food nutrition points. A reduction of 0.1 removes ten percent of the hunger range. NaN/infinite inputs and non-positive reductions are rejected.

import com.fyxe.ffanimalcare.api.AnimalHungerApi;

// After your custom feeding system has consumed its item:
boolean accepted = AnimalHungerApi.fed(animal, player, 0.1);

// After custom grazing has actually completed:
AnimalHungerApi.grassEaten(animal);

// After your own successful offspring creation, once per parent:
AnimalHungerApi.breedingCompleted(parent);
AnimalHungerApi.breedingCompleted(partner);

Portable callbacks

Register a HungerListener with AnimalHungerApi.registerListener. It returns a removable HungerEvents.Subscription; call close() when your integration is disposed. Listeners run in registration order. Registration can occur during mod setup, while entity operations belong on the game thread.

CallbackUse
allowTracking(Animal)Return false to leave another system's animals untouched. Pure eligibility veto; may run on either logical side. It cannot override config exclusions.
modifyRate(Rate)Read animal/perTick and setPerTick to adjust gain after config/datapack factors. Zero prevents gain; final rate is bounded 0..1.
beforeChange(Change)Inspect animal, previous, reason and activating. cancel(), setCurrent(float), or setRecoveryDelayTicks(int) changes the proposal. Delay applies only to an actual drop.
afterChange(Animal, float previous, float current, HungerChangeReason)Observe committed value changes/activation. Does not fire for canceled or unchanged non-activation operations.
afterFeeding(Animal, Player, HungerChangeReason)Observe completed player/mod feeding or grass eating. Player is null for grazing or a caller-supplied custom source. Untamed cat/parrot callbacks wait for vanilla consumption.
beforeBreeding(Breeding)cancel() vetoes natural or API-started love mode.
afterBreeding(Animal, long worldTime, long delayTicks)Observe a parent's recorded offspring/pregnancy time and chosen cooldown.
beforeStarvation(Starvation)cancel() or setDamage(float) modifies a loaded starvation hit.

Change reasons are NATURAL, PLAYER_FEEDING, GRASS, MOD_FEEDING, API and ACTIVATION. For first player/mod feeding, previous is the configured initialHunger before applying the meal, and activating is true. Canceled natural gains consume their elapsed interval; they are not accumulated for later catch-up.

Modify event payloads inside callbacks; do not call hunger mutations recursively. Recursive mutations return false and nested callback dispatch is suppressed. Non-finite setter inputs are ignored. RuntimeException from a listener is logged and that listener is removed, allowing other integrations to keep running. Internal event dispatch helpers are not part of the supported integration contract.

import com.fyxe.ffanimalcare.api.*;
import net.minecraft.world.entity.EntityType;
import net.minecraft.world.entity.animal.Animal;

HungerEvents.Subscription subscription = AnimalHungerApi.registerListener(new HungerListener() {
    @Override public boolean allowTracking(Animal animal) {
        // Example: this integration lets another system own bees.
        return animal.getType() != EntityType.BEE;
    }
    @Override public void beforeChange(HungerEvents.Change event) {
        if (event.reason == HungerChangeReason.GRASS) event.setRecoveryDelayTicks(10);
    }
    @Override public void beforeStarvation(HungerEvents.Starvation event) {
        if (event.animal.hasCustomName()) event.cancel();
    }
});

// When this integration is disposed:
subscription.close();

Data and compatibility boundaries

For static entity/tag/regex rate adjustments, prefer datapack rules. Use callbacks for dynamic state-dependent policy, and the API feeding/grazing/breeding helpers when your own logic bypasses vanilla hooks.

Only Animal subclasses are supported. The API keeps FFAnimalCare's sync, persistence, movement effects and recovery behavior consistent, but does not implement another mod's food consumption, pairing AI or pregnancy logic. Full snapshots are server-only; clients receive hunger/activation. No interactive client or third-party animal mod integration has been verified by these examples.

Care in API version 2

The server snapshot now includes careExperience() and careLevel(). Experience is saved; level is derived from current configuration. Only hunger/activation synchronize to clients. Effective rates include care before rate callbacks. Recompile integrations against com.fyxe.ffanimalcare.api and API version 2. Diets affect ordinary player feeding; fed takes an explicit normalized reduction and does not apply a diet multiplier.
