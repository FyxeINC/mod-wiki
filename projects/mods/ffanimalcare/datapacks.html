Hunger-rate rules

FFAnimalCare 0.3.0 adds server datapack rules that multiply hunger gain for eligible animals. Files live at data/<namespace>/ffanimalcare/hunger_rates/<name>.json, with the same custom directory on every supported version. Use a pack.mcmeta appropriate for your Minecraft version.

The file ID is its namespace and relative filename, for example my_pack:farms. Rules apply only to animals already covered by the mod and do not activate wild animals or override exclusions.

JSON schema

{
  "entities": ["minecraft:pig"],
  "tags": ["my_pack:farm_animals"],
  "regex": ["examplemod:.*"],
  "multiplier": 0.75,
  "enabled": true
}
FieldDefaultMeaning
entities[]Explicit entity IDs. Missing optional mods are allowed and simply do not match.
tags[]Entity-type tag IDs without a leading #. Membership comes from the current server tags.
regex[]Java regex patterns matched against the entire namespace:path entity ID.
multiplierRequiredFinite number from 0 to 100. 1 is unchanged, 1.1 is 10% faster, 0.75 is 25% slower, 0 stops hunger gain.
enabledtrueSet false to disable this rule while keeping a valid definition.

At least one selector is required. Selectors within a file are ORed: a match in any list applies that file once. Every matching file multiplies together, in deterministic file-ID order. There is no exact-ID priority over tags or regex. Zero stops gain even if other matching rules increase it; it does not disable starvation damage for an animal already at the damage threshold.

Default pig rule and overrides

The shipped ffanimalcare:pigs rule is:

{
  "entities": ["minecraft:pig"],
  "multiplier": 1.1
}

Replace data/ffanimalcare/ffanimalcare/hunger_rates/pigs.json in a higher-priority datapack to change it. To disable it:

{
  "entities": ["minecraft:pig"],
  "multiplier": 1.1,
  "enabled": false
}

Adding a different file stacks with the default rather than replacing it. For example, a new pig multiplier of 2 produces a combined 2.2; replace the shipped file if you want exactly 2.

Tags and regex examples

For Minecraft 1.21.1 and 1.21.11, define data/my_pack/tags/entity_type/farm_animals.json. On 1.20.1 and 1.20.6, the folder is tags/entity_types.

{
  "values": ["minecraft:cow", "minecraft:pig", "minecraft:sheep"]
}

Then create data/my_pack/ffanimalcare/hunger_rates/farms.json:

{
  "tags": ["my_pack:farm_animals"],
  "multiplier": 0.75
}

Cows and sheep get 0.75 of their previous rate; pigs get 1.1 * 0.75 = 0.825 because their default rule also matches. For optional mod animals, a full-match pattern can select a whole namespace:

{
  "regex": ["examplemod:.*"],
  "multiplier": 1.25
}

minecraft:pig matches pigs, .*pig.* matches IDs containing pig, and pig alone does not match minecraft:pig. Standard Java regex syntax is supported; escape backslashes using normal JSON escaping.

Reload and rate composition

Use /reload to update rules and entity tags. Each reload replaces the previous table; malformed IDs, patterns, selectors or multipliers are logged and skipped per file. Higher-priority packs replace files with the same ID according to normal datapack rules.

Effective rate combines the base config, optional baby and saved individual multipliers, all matching datapack rules, and the API rate callback. Final gain is capped at 1 hunger per world tick. Rules affect hunger gain only, not the food reduction amount or movement modifier formula.

Chunk catch-up uses current rules, age and config when the animal resumes. It excludes the saved recovery pause and never catches up damage. Rules are server-only; clients receive the resulting hunger through normal mod synchronization. For custom grazing or feeding logic see Modding API.

Diet types and food effectiveness

Put diet files at data/<namespace>/ffanimalcare/diet_types/<name>.json. These server-only rules reload with /reload. No built-in diet changes vanilla foods. Top-level entities, tags (entity-type tags, without #) and regex select mobs; at least one selector is required. Selectors are ORed and regex matches the full entity ID. Optional enabled defaults true.

foods is a required array. Each entry accepts lists of items, tags (item tags, without #) and regex; at least one food selector is required. Multiple IDs/selectors per entry are ORed. multiplier defaults 1 and must be finite, between 0 and 100. It scales hunger relief: 2 means twice as filling, 0.5 half as filling, and 0 consumes food without hunger relief. Unknown but valid mod IDs are allowed; malformed IDs, patterns or values reject the file.

{
  "entities": ["minecraft:cow", "minecraft:sheep"],
  "tags": ["my_pack:herbivores"],
  "regex": ["othermod:.*_deer"],
  "foods": [
    {"items": ["minecraft:wheat", "minecraft:carrot"], "multiplier": 1.5},
    {"tags": ["my_pack:animal_snacks"], "multiplier": 0.5},
    {"regex": ["minecraft:.*_seeds"], "multiplier": 0.75}
  ]
}

For covered animals, matching diets replace vanilla feeding foods. All matching diets contribute accepted foods; when entries overlap, the highest matching multiplier wins, with no stacking. Empty foods accepts no meals. Disabled diets do not cover animals. Animals with no matching diet keep vanilla food acceptance, including supported horse/parrot extras.

Relief is (nutrition + saturation) × foodModifier × multiplier; items without food properties use fallback nutrition/saturation. Refusal and first-feed activation still apply. Diet-only foods can be fed even if vanilla does not recognize them. Vanilla cat/parrot foods retain taming; added foods feed without attempting taming. Diets do not change grazing, temptation foods, or custom API feeding. Custom mod interactions may require integration or exclusions.
