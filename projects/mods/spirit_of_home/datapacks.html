Datapacks

The mod adds reloadable spirit names, activity categories, attribute modifiers and welcome status effects alongside vanilla recipes, drops and mining tags. For 1.21.1, a datapack uses pack_format: 48 in pack.mcmeta.

Spirit name pools

Each data/<namespace>/home_names/<id>.json contributes names and descriptors. Override data/spirit_of_home/home_names/default.json to replace the bundled pool, or use a new resource id in your namespace to expand it. The mod combines all valid loaded names and all valid loaded descriptors, then independently picks one of each with a space between them.

{
  "names": ["Anwen", "Bramble", "Juniper", "Wren"],
  "descriptors": ["of the Hearth", "Under the Eaves", "Housemate", "by the Kettle"]
}

Both arrays are required, nonempty, and contain nonblank printable strings up to 48 characters without controls or formatting codes. Each occurrence is a random choice; repeating an entry increases its weight. Identical resource ids follow normal datapack priority. A malformed file is logged and skipped. If no valid pools remain, new spirits use Anwen of the Hearth. The bundled pool includes all requested names/descriptors plus additional garden, hearth and household choices.

Run /reload to apply changes. New spirits use the updated pools; existing generated or manually renamed spirits retain their names and colors. Colors are generated in code and cannot be configured with these files. Category activity gains and attribute benefits are datapack-defined; experience conversion, spawn protection and attunement use mod code and configuration.

Home categories

Define each category in data/<namespace>/home_categories/<path>.json. Its resource id is namespace:path. One file is one category; there is no fixed category count. The bundled ids are spirit_of_home:rest, craft, board, shelter and vigil (all in the spirit_of_home namespace). Files sort by resource id in the screen; more than five categories use scroll pages. Values belong to the id, so renaming a definition retains its meter, while changing its id starts a new meter.

{
  "name": "Craft",
  "color": 15316827,
  "actions": [
    { "type": "craft", "amount": 0.02 },
    { "type": "place_block", "amount": 0.05, "target": "#minecraft:planks" }
  ],
  "enabled": true
}

name is required printable, nonblank text up to 100 characters. It may be a client translation key (the shipped definitions use spirit_of_home.category.rest, craft, board, shelter and vigil), or a literal name when no translation exists. Tooltips translate this name and derive basic activity hints from action types, omitting the category id and meter percentage; target filters still control actual gains. color is a required decimal RGB integer from 0 to 16777215. actions is a required array and may be empty. Each action requires type and amount (0 to 1); optional target is an exact resource id or #tag. An omitted target matches every subject of that action. Multiple matching actions add their gains before the player contribution multiplier. enabled defaults to true. Override a bundled file with enabled=false and actions=[] to remove that category. Higher-priority packs replace identical ids; additional ids add categories. Invalid files are logged and skipped. There is no hardcoded fallback list.

These action types are supplied by the mod; datapacks choose which types, target filters and gains feed each category. Run /reload to update definitions, commands and open screens. Existing values persist for active ids. Disabled or removed ids lose stored values without XP at the next decay update. Values never exceed 1; excess gains are lost. All loaded spheres covering the action location receive gains independently, after each action amount is scaled through actionGainEquation using the player's Minecraft XP level, then multiplied by 100% for attuned players or the configured visitor multiplier. Default scaling is amount * (1 + level / 30); category JSON amounts remain the base gains.

Server configuration controls radius, decay and XP conversion. Decay uses elapsed world ticks and catches up after chunk reload; stopped-server time and skipped night/day time do not count. Defaults consume 0.01 per 1200 ticks while someone is home, twice that with nobody inside the sphere (awayDecayMultiplier=2). Unloaded catch-up uses the away rate; presence changes and unloads settle their previous rate first. Both rates use the same XP per consumed unit. They award 100 XP per full value consumed (0.2 = 20 XP). Fractional XP is retained. Category commands and configuration are documented on the Overview.

Home attributes

One data/<namespace>/home_attributes/<path>.json defines one transient player attribute modifier. Add new ids for additional modifiers, or override a shipped id to replace or disable it. Definitions reload with /reload; removed, disabled, retargeted and expired modifiers are removed on the next five-tick refresh. Unrelated modifiers are preserved. Invalid files are logged and skipped, with no hardcoded fallback. Unknown attributes or attributes absent from the player are skipped.

{
  "source": "home",
  "attribute": "minecraft:generic.movement_speed",
  "amount": "0.1 * (level + 1) * strength",
  "operation": "add_multiplied_total",
  "min_level": 0,
  "max_level": 100,
  "enabled": true
}

Required: source (home, homesick or welcome), attribute (registered resource id, including modded attributes) and amount (a formula string). Optional: operation (add_value, add_multiplied_base or default add_multiplied_total); min_level/max_level (inclusive spirit level bounds, default 0/100); enabled (true); and duration_ticks (formula string, default "600", used only for welcome). Keep required fields when overriding with enabled=false. Bounds must be ordered and within 0–100.

Formula variables: level is the active attuned stone's level, or 0 away from home; strength is 1 in the inner half of its spherical range and fades linearly to 0 at the boundary, or 0 away; spiritless is raw absence 0–1; severity is normalized homesickness 0–1; player_level is Minecraft XP level. Amounts are used exactly as written: include strength or severity yourself if desired. Formulas support +, -, *, /, %, ^, parentheses, abs, min, max, clamp, pow, sqrt, floor, ceil and round. Invalid syntax/unknown variables reject the file. Nonfinite or zero amounts apply nothing. Finite amounts clamp to +/-1000000, with multiplicative reductions additionally bounded at -0.95. Operations add a flat value, add a fraction of the base, or multiply the total by 1+amount.

Home definitions apply only inside your attuned sphere; homesick definitions apply only while homesick. Welcome definitions begin once a homesick return grants either player or spirit XP. They snapshot the post-reward spirit/player levels, pre-reset spiritless/severity and strength=1. Duration and amount use that snapshot, so they can scale with absence and do not reset while standing at home. Durations cap at 1728000 ticks; nonpositive/nonfinite values disable the modifier. Attribute buffs continue away from home and through dimension travel, expire within the five-tick update resolution, and clear on death/logout/server stop. A new rewarded return refreshes them. Reload updates active welcome attributes against the original start and snapshot.

All shipped attributes use add_multiplied_total. Home and welcome +20% mining modifiers multiply to 1.2 × 1.2 = 1.44. To add a movement penalty, create a homesick definition with attribute minecraft:generic.movement_speed and amount "-0.2 * severity". Returns below threshold, or with both XP formulas producing zero, grant none.

Welcome status effects

data/<namespace>/welcome_effects/<path>.json grants one vanilla or modded status effect on the same experience-bearing welcome. These complement welcome attribute modifiers:

{
  "effect": "minecraft:regeneration",
  "duration_ticks": "200",
  "amplifier": "0",
  "min_level": 0,
  "max_level": 100,
  "particles": false,
  "icon": true,
  "enabled": true
}

Required: effect id and duration_ticks formula. Optional: amplifier formula ("0", meaning level I), min_level/max_level (0/100), particles/icon/enabled (true). Formulas use the same welcome snapshot and syntax as home_attributes. Finite durations of at least 1 tick truncate to integers and cap at 1728000; finite nonnegative amplifiers truncate and cap at 255. Other results skip the effect. Invalid files are logged/skipped; unknown effects are skipped. Definitions apply in resource-id order with vanilla effect merging, persistence, death and expiry rules. They are granted once, not refreshed every five ticks; reload affects future grants and does not remove an existing effect from another source.

The default spirit_of_home:regeneration gives Regeneration I for 200 ticks (10 seconds), with no particles and a visible icon. Override its file with enabled=false to disable it; new ids add more effects. Removing attribute buffs does not disable these effects, or vice versa.

Crafting recipe

Override data/spirit_of_home/recipe/cornerstone.json to change the ingredients or result. The shipped recipe is:

{
  "type": "minecraft:crafting_shaped",
  "category": "building",
  "pattern": [
    " B ",
    " L ",
    "SSS"
  ],
  "key": {
    "B": {
      "item": "minecraft:bone"
    },
    "L": {
      "item": "minecraft:stone_slab"
    },
    "S": {
      "item": "minecraft:stone"
    }
  },
  "result": {
    "id": "spirit_of_home:cornerstone",
    "count": 1
  }
}

The id is spirit_of_home:cornerstone. Minecraft 1.21.1 uses the singular recipe folder and result.id. The recipe book unlock is data/spirit_of_home/advancement/recipes/building_blocks/cornerstone.json; override it if you change the unlock ingredient.

The Spirit Totem recipe is data/spirit_of_home/recipe/spirit_totem.json: pattern ["B", "W", "W"], B is minecraft:bone, W is the minecraft:logs item tag, and the result is one spirit_of_home:spirit_totem. Its recipe-book advancement is data/spirit_of_home/advancement/recipes/building_blocks/spirit_totem.json, unlocked by acquiring bone. Both can be overridden normally.

        {
          "type": "minecraft:item",
          "name": "minecraft:bone"

        {
          "condition": "minecraft:survives_explosion"
        }
      ]
    },
    {
      "rolls": 1,
      "entries": [
        {
          "type": "minecraft:item",
          "name": "minecraft:stone_slab"
        }

      "conditions": [

    {

The shipped table returns one bone, one stone slab and three stones. No correct tool is required. Creative breaking follows vanilla no-drop behavior. Datapacks can override these ingredient drops.

Spirit Totem self-drops are defined in data/spirit_of_home/loot_table/blocks/spirit_totem.json. Its axe tag is data/minecraft/tags/block/mineable/axe.json.

Mining tags

The Cornerstone is added to minecraft:mineable/pickaxe by data/minecraft/tags/block/mineable/pickaxe.json, with replace: false. The tag remains available for tool classification, but the mod bypasses mining-speed calculations and does not require a correct tool for drops. Tag changes cannot shorten its fixed mining duration. Attribute benefits use the home_attributes definitions; aura radius uses server configuration.

Applying changes

Install the datapack in the world's datapacks folder and run /reload. Existing placed blocks keep their registry id. Resource-pack models and textures are separate from datapack recipes and drops.
