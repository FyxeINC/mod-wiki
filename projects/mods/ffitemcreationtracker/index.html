FFItemCreationTracker

Modrinth ↗CurseForge ↗Source ↗

Overview

Records who created an item, when, where, and how.

Features

  • Stamps crafted and other newly created items with synced provenance.
  • Other mods can add custom creation sources and extra fields.
  • OP commands (/ffitemcreationtracker info / stamp) to inspect and manually set the stamp on the item in hand. No command removes a stamp.
  • Client options to show the tooltip on one line or stacked one detail per line, set separately for the normal and Shift tooltips.
  • Remembers the other players who change a stamped item and lists them after the maker (Modified by Alex, Sam).
  • Optional weather, depth, and coordinate details, hidden by default. Coordinates are only recorded when the server allows it.

FFUtilities 0.2.8 is included in this mod JAR; no separate library download is needed. Fabric players also need Fabric API.

How stamping works

When you craft, smelt, take an anvil result, enchant, brew, cut at a stonecutter, weave at a loom, reel in a catch, or take an item from any menu output slot, the item is stamped. Other mods can stamp extra cases through the API. Hover it to see a line such as Created by Steve, on day 12, in Plains.

Brewing is stamped when you take the potion from a brewing stand (Brewed by Steve). The stand credits the last online player who put an ingredient or fuel into it; potions pulled out by a hopper, or after a server restart, get no stamp. Stonecutter results read Cut by Steve and loom results Woven by Steve.

Modification history

The first maker keeps the stamp. When a different player changes the item (anvil, enchanting table, smithing table, or any output that keeps the stamp), their name is added to a history shown after the maker as Modified by Alex, Sam. The maker is never listed and each player appears once. The oldest name is dropped when the history is full. Turn it off with server trackModifications; names already on items stay. The client showModifiers setting controls where it is drawn.

Stamps live on the item as a synced data component. Drop the sword, mail it, or hand it to a friend and they still see your name.

Custom crafting screens (Farmer's Delight cooking pot, other result slots) are stamped when you take the output; no per-mod module is needed. Create mechanical crafters and other unattended machines don't stamp a player, because nobody took the item from a menu.

Maker names use a color hashed from the username, so every client paints Steve the same way. Override with Name=#RRGGBB.

Defaults

  • Survival only (Creative is off)
  • Unstackable items only, so cobble and bread keep stacking
  • First maker wins (later crafts don't overwrite)
  • Crafted by Steve on the normal tooltip (source and maker). Day and dimension on Shift (showTime, showDimension); biome, moon, weather, depth and coordinates hidden (NEITHER), extras on Shift
  • Each detail has its own BASIC / ALT / NEITHER setting
  • One detail per line under the Crafted by Steve line (VERTICAL). Set basicLayout (normal tooltip) and/or altLayout (Shift tooltip) to HORIZONTAL for one long line
  • Time text is GAME_DAY, EXACT or BOTH

Extra details (off by default)

  • Weather: in the rain, in the snow, during a thunderstorm or in clear weather. Turn on showWeather.
  • Depth: deep underground, underground, underwater, on the surface or high up. Not recorded in the Nether. Turn on showDepth.
  • Coordinates: at (120, 64, -300). Turn on showCoordinates. The server must also turn on recordCoordinates, which is off by default because anyone who sees the item can read where it was made.

Weather and depth are recorded by default (server recordWeather / recordDepth), so turning the client setting on later also works for items made earlier.

Configuration

Server config: ffitemcreationtracker-server.toml (who gets stamped). Client config: ffitemcreationtracker-client.toml (what you see).

Choosing which items are stamped

The server whitelist and blacklist take item IDs or item tags, one per line:

minecraft:diamond_sword
#minecraft:pickaxes
  • The blacklist always wins.
  • If the whitelist has any entries, only those items (minus the blacklist) are stamped.
  • If the whitelist is empty, every item except the blacklist is stamped, then trackStackables may still skip stackable items.

Already stamped items keep their data if you later tighten the lists. Tooltips still hide blacklisted items. There is no datapack folder; datapack item tags work in these lists.

Commands

Server operators (permission level 2) can check and set the stamp on the item in their main hand:

/ffitemcreationtracker info
/ffitemcreationtracker stamp <source> [player]

info prints the creator, source, a Modified by: line when others changed the item, day, exact time, dimension, biome, moon phase and any extras. stamp writes a new stamp or replaces the existing one, attributed to the given player (or you), using your current day, dimension, biome and moon phase. <source> accepts the built-in IDs (crafted, smelted, anvil, smithing, enchanted, traded, fished, brewed, stonecut, loomed, unknown) or a custom ID another mod registered, such as mymod:cooking (no quotes needed; tab completion lists every registered source). Command messages are translatable and info prints the stamp time in UTC. There is no command to remove a stamp.
