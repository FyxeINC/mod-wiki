Datapacks

FFItemWeight reads two datapack formats: item weights and encumbrance bands. Use /reload after changing a datapack; the server log then prints an audit of what loaded.

Item weights

Path: data/<namespace>/item_weights/<name>.json

{
  "comment": "optional",
  "weights": [
    { "id": "mymod:widget", "weight": 2.5 },
    { "id": "mymod:.*_ore", "weight": 6.0, "regex": true },
    { "id": "mymod:boss_core", "weight": 50.0, "force": true }
  ]
}
Field Default Meaning
id required Item ID, or a Java regex on the full registry ID when regex is true
weight required unless weight_from is set Unit weight (one item). Clamped by maxUnitWeight
weight_from unset Exact source item ID; locks this item to that item's final unit weight instead of supplying weight
regex false Treat id as a regex
force false Lock the base. Recipes can't overwrite it

Resolution order: valid weight_from references take precedence over numeric bases and recipes; otherwise forced exact, forced regex (HEAVIEST or LIGHTEST), non-forced exact, longest non-forced regex, recipes, then defaultWeight.

Sharing another item's weight

To keep variants equal to another item, use an exact reference (no numeric weight, no regex):

{ "weights": [{ "id": "minecraft:oxidized_copper", "weight_from": "minecraft:copper_block" }] }

References are always locked, regardless of force. They follow recipe-derived weights, configuration clamps and fallback weights, and work with recipe calculation disabled. Chains are supported; missing items, self-references and cycles are warned about and ignored. Stack contents are still counted separately.

The defaults cover all 63 exposed, weathered, oxidized and waxed copper variants across blocks, cut blocks, stairs, slabs, chiseled blocks, grates, bulbs, doors and trapdoors. Each follows its matching unwaxed, unoxidized shape. Override the same resource path to replace these defaults. Within loaded files, a later exact numeric entry replaces a reference and vice versa; use the same resource path for predictable pack overrides.

Use force: true for balance anchors and items with bad recipe graphs. Leave normal craft chains unforced so tools and armor can derive from their ingredients.

Shipped packs

Under data/ffitemweight/item_weights/:

  • default_minecraft.json: vanilla exact IDs and minecraft: regex only
  • default_compat.json: family regex that skips the minecraft namespace
  • Specialized packs where a mod needs its own names or forced anchors: default_create.json, default_create_aeronautics.json, default_farmersdelight.json, default_supplementaries.json, default_handcrafted.json, default_macaws.json, default_tide.json, default_naturalist.json, default_benssharks.json

Override any exact id from another datapack (optional force). The longer regex wins when several non-forced patterns match.

Recipe derivation

Server config calculation: multi-pass HEAVIEST or LIGHTEST, recipe type modifiers, ignored types, and skip patterns for recycling. Repairs and dyes (where the result is also an ingredient) are skipped. Diamond to netherite smithing still applies unless the result is forced.

Shipped modifiers cover vanilla plus Create processing and Farmer's Delight cooking / cutting (and a few add-ons). Types that flatten weights are ignored by default: minecraft:smithing_trim, create:conversion, sawmill:woodcutting, corail_woodcutter:woodcutting, woodworks:sawing.

On server start and /reload the log prints an audit (disable with calculation.auditLog): JSON packs, recipe types used or skipped, and items still on defaultWeight. Cap the ID list with auditFallbackListLimit.

ignoredRecipeTypes = ["minecraft:smithing_trim", "sawmill:woodcutting", "mymod:assembler"]
containerContentModifiers = [".*:.*_shulker_box=0.5"]

If many items stay on the default weight, add JSON bases and use /ffitemweight defaults or /ffitemweight exportdefaults for the full list. If a machine mod inflates materials, ignore its recipe types or force anchors.

Encumbrance bands

Path: data/<namespace>/ffitemweight/encumbrance/<id>.json

Override a built-in by shipping the same path, for example data/ffitemweight/ffitemweight/encumbrance/heavy_load.json. Gameplay and other mods compare level, not the display name.

{
  "level": 3,
  "display_name": "Heavy Load",
  "color": "#FFAA00",
  "capacity": 2000,
  "icon": "ffitemweight:textures/gui/encumbrance/heavy_load.png",
  "shake": 1.5,
  "effects": [
    { "id": "minecraft:slowness", "amplifier": 0 }
  ],
  "attributes": [
    { "id": "minecraft:generic.movement_speed", "operation": "multiply_total", "amount": -0.20 }
  ]
}
Field Meaning
level Integer band. 0 is lightest
display_name HUD and tooltip label only
color #RRGGBB
capacity Base max total weight before player capacity scaling
icon HUD texture ID
shake Target HUD icon amplitude in pixels. Interpolates from the previous band value (initially zero) to this value across the band's capacity-adjusted weight range. The final band uses the preceding range width instead of its sentinel capacity, then caps at its target. Set all bands to 0 for no shake
effects Potions applied while this band is active. Amplifier 0 is potion level I
attributes Attribute modifiers for this band (add, multiply_base, multiply_total). Attribute IDs follow the game version, so on 1.21.11 use minecraft:movement_speed instead of minecraft:generic.movement_speed

A player is in the first band whose scaled capacity is at least their total weight:

threshold = capacity * levelMultiplier + flatBonus
