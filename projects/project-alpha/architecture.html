Notable decisions

Why a queue instead of doing everything inline?
Anything that can fail or take more than a second or two — sending email, generating a report — goes through the worker so a slow dependency never blocks the request that triggered it.
Why Redis for cache instead of in-process memory?
The API runs as more than one instance, so cache state needs to live somewhere shared. Redis also gives us a place to put rate-limit counters later.
